# Synthetic reference vectors

This optional tool replays a small, frozen corpus through the current Vanetza
codec. It does not depend on the original intersection-model application.

The corpus contains one MAPEM, ten SPATEM snapshots, one SREM request and one
SSEM response. All inputs describe a synthetic example, not a road installation.
The response state is `processing`; it is not evidence of a priority grant.

## Build and replay

```sh
cmake -S . -B build -DBUILD_TESTS=ON -DBUILD_REFERENCE_VECTORS=ON
cmake --build build --target reference-vector-codec GTest_ReferenceVectors
ctest --test-dir build -R '^ReferenceVector(s|Replay)$' --output-on-failure
python3 tools/reference_vectors/replay.py \
  vanetza/asn1/tests/reference_vectors/intersection_01 \
  --codec build/bin/reference-vector-codec
```

The executable path can differ with the generator. The replay starts from each
committed XER seed, produces UPER, decodes it back to XER, and requires both files
to match the committed bytes. Temporary output is removed automatically; use
`--output PATH` to retain it. Do not use the corpus directory as output.

For a single message:

```sh
build/bin/reference-vector-codec srem xer-to-uper \
  vanetza/asn1/tests/reference_vectors/intersection_01/srem_tram_request.xer \
  /tmp/srem.uper
```

Supported message names are `mapem`, `spatem`, `srem` and `ssem`; directions are
`xer-to-uper` and `uper-to-xer`. Invalid arguments, input or output produce a
nonzero exit status. The GoogleTest target also covers malformed input.

## Cross-decoder check

```sh
python3 -m venv .venv-vectors
. .venv-vectors/bin/activate
python -m pip install -r tools/reference_vectors/requirements.txt
python tools/reference_vectors/check_vectors.py \
  vanetza/asn1/tests/reference_vectors/intersection_01
python -m unittest discover -s tools/reference_vectors -p 'test_*.py' -v
```

On Windows, activate `.venv-vectors\Scripts\Activate.ps1`. Python 3.10 or newer is
required. The checker uses the installed `pycrate_asn1dir.ITS` module from pycrate
0.8.1; it does not download or compile standards. It checks message IDs, lengths,
UPER re-encoding and the decoded values against XER. Empty manifests, missing
files and differences fail. This is a cross-decoder consistency test, not an
independent semantic oracle or a claim of standards conformance/interoperability.

## Provenance and limits

The original bytes were published in
[vanetza-tlm PR #2](https://github.com/AlexeyBorovskoy/vanetza-tlm/pull/2), revision
`c309ffd4704f4dc6c3c03e9c50dfdbce9b8809e4`. They were generated by an example intersection application which is
not part of this contribution. `manifest.json` preserves those original scenario
descriptions and timestamps; their timezone was not recorded. This tool
reproduces the encodings from frozen XER, not the original traffic model or its
timing decisions. `provenance.json` records exact upstream revisions, hashes and
the decoder module used for local validation. No ASN.1 standard text is included.

Fixtures are under `vanetza/asn1/tests/reference_vectors/intersection_01`. To add a
case, commit both encodings and a manifest entry, update provenance hashes and
run both replay and cross-decoder checks. Changing the model's semantics requires
separate evidence; updating hashes alone is not validation.
